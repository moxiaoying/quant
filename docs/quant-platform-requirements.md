# 量化交易管理系统项目需求文档

版本：v1.0  
日期：2026-10-01  
适用工程：`stock-master`

## 1. 文档目标

本文档将现有 Spring Boot + MySQL + Node Web 工程整理为一套可持续演进的量化交易管理系统，作为产品、前端、后端、数据和测试工作的共同基线。

第一阶段目标不是一次性拆成微服务，而是在现有单体工程内形成清晰的业务模块边界，先完成可运行、可回测、可风控、可审计的量化平台基础。

## 2. 当前工程基线

### 2.1 已有能力

| 领域 | 当前实现 |
|---|---|
| 后端 | `stock-service`，Spring Boot 2.5.4、Gradle、Java 8 |
| 前端 | `stock-web`，Node 静态文件服务、API 代理 |
| 数据库 | MySQL，当前使用 `stock_master` |
| 行情 | 股票基础信息、日线指数、部分外部行情抓取 |
| 交易 | 东方财富接口封装、普通股票/ETF/可转债交易请求 |
| 策略 | 网格类策略、交易规则、定时任务执行 |
| 任务 | `ScheduledTasks`、`task`、`execute_info` |
| 用户 | 用户登录、密码修改、Token 缓存设计 |
| 通知 | 机器人 Webhook 消息通知 |

### 2.2 当前主要缺口

- 登录 Token 校验链路需要修复和补充测试。
- 当前没有独立的回测引擎。
- 策略、风控、交易执行边界耦合较强。
- 没有完整账户资产、持仓快照和组合净值模型。
- 没有统一订单状态机和交易审计链路。
- 缺少 Mock Broker，无法安全验证自动交易。
- 前端页面以静态 HTML 为主，缺少统一状态管理和组件规范。

## 3. 产品定位与用户角色

系统定位为个人或小型团队使用的量化交易管理平台，支持行情采集、策略配置、历史回测、模拟交易和受控实盘交易。

### 3.1 用户角色

| 角色 | 权限 |
|---|---|
| 管理员 | 用户、系统配置、数据源、任务、风控和审计管理 |
| 研究员 | 行情查询、策略编辑、回测、报告查看 |
| 交易员 | 账户、持仓、订单、策略启停、人工交易 |
| 只读用户 | 查看行情、持仓、报告和任务状态 |

## 4. 总体技术架构

```text
Web 管理端
  ├─ 仪表盘
  ├─ 行情中心
  ├─ 策略中心
  ├─ 回测中心
  ├─ 交易中心
  ├─ 风控中心
  └─ 报表与系统管理
          │ REST / WebSocket
API 与认证层
          │
模块化后端单体 stock-service
  ├─ auth       用户、角色、Token
  ├─ market     行情、基础资料、交易日历
  ├─ strategy   策略、信号、规则
  ├─ backtest   回测任务、撮合、绩效
  ├─ trade      Broker 适配、订单、成交
  ├─ risk       事前、事中、事后风控
  ├─ portfolio  账户、资产、持仓、净值
  ├─ scheduler  定时任务和重试
  ├─ report     报表和导出
  └─ audit      操作、订单、风险审计
          │
MySQL + Caffeine/Redis + 可选消息队列
          │
行情源、券商接口、OCR、通知服务
```

第一期继续使用模块化单体；当行情采集、回测和交易并发明显增长时，再拆分 `market-data-service`、`backtest-service` 和 `trade-service`。

## 5. 功能需求

### 5.1 用户与权限

功能：

- 用户登录、退出、密码修改和 Token 刷新。
- 角色、权限和数据范围控制。
- 登录失败次数限制和会话过期。
- 所有敏感操作写入审计日志。

后端要求：

- 密码只保存单向哈希，不保存明文。
- Token 校验必须在每次受保护请求中执行。
- 交易、风控、系统配置接口必须做细粒度权限控制。

前端页面：

- 登录页。
- 个人资料和修改密码。
- 用户列表、角色列表、权限配置。

### 5.2 行情与基础数据

功能：

- 股票、ETF、指数、可转债基础信息。
- 实时行情、日线、分钟线。
- 交易日历和节假日。
- 数据采集任务、失败重试和补采。
- 数据质量检查：缺失、重复、异常价格、时间错位。

建议数据表：

```text
stock_info
stock_daily
minute_bar
holiday_calendar
market_sync_job
```

数据表职责统一如下：

- `stock_info` 只保存证券基础资料，不保存历史价格；
- `stock_daily` 保存股票、ETF 和指数日线行情，Baostock 数据统一进入此表；
- `daily_index` 暂时保留为数据库兼容表，但运行时代码已经切换到 `stock_daily`；
- `v_stock_daily` 作为基础资料与日线行情的统一查询视图；
- 迁移脚本位于 `sql/stock_daily_migration.sql`，可重复执行且不会删除旧数据。

数据中心前端采用“任务表单”布局，任务列表展示任务类型、执行频次、起止时间、同步方式、运行状态和操作入口。当前已接入行情数据获取任务；执行频次和删除/修改入口作为任务编排扩展位，后端定时调度接口完成前暂不宣称自动执行。

### 5.3 策略中心

功能：

- 策略列表、版本、参数和启停。
- 策略适用标的和账户绑定。
- 策略信号记录。
- 策略运行日志。
- 模拟/实盘环境隔离。

策略接口建议：

```java
public interface Strategy {
    List<Signal> generateSignals(MarketContext context);
}
```

现有 `trade_strategy`、`trade_rule` 可作为第一期基础；后续增加 `strategy_version`、`strategy_signal`。

### 5.4 回测中心

功能：

- 选择策略、标的、日期区间和参数。
- 支持手续费、滑点、涨跌停和交易时间模拟。
- 回测任务异步执行。
- 查看收益曲线、回撤、胜率、夏普比率、交易明细。
- 支持多个回测结果对比。
- 导出 CSV/Excel 报告。

回测流程：

```text
历史数据 → 策略信号 → 模拟撮合 → 资产/持仓计算 → 指标统计 → 回测报告
```

建议数据表：

```text
backtest_job
backtest_trade
backtest_position
backtest_metric
backtest_equity_curve
```

### 5.5 交易中心

功能：

- 券商账户登录和状态检查。
- 查询资金、持仓、委托和成交。
- 买入、卖出、撤单。
- 普通股票、ETF、可转债扩展。
- Mock Broker 模式。
- 委托状态同步和异常重试。

交易适配器：

```text
BrokerAdapter
  ├─ EastMoneyAdapter
  ├─ MockBrokerAdapter
  └─ FutureBrokerAdapter
```

任何策略都只能提交标准化订单，不能直接调用东方财富接口。

### 5.6 风控中心

风控必须位于策略信号和订单执行之间。

风控规则：

- 单票最大仓位。
- 单日最大亏损。
- 单笔最大金额。
- 最大总仓位。
- 价格偏离限制。
- 涨跌停和停牌检查。
- 交易时间检查。
- 余额和可用资金检查。
- 账户、策略和标的黑名单。
- 全局紧急停止。

风控结果必须返回：

```text
PASS / REJECT / WARNING
```

并记录 `risk_event`。

### 5.7 账户与组合

功能：

- 账户资金和持仓。
- 冻结资金、可用资金和市值。
- 组合净值和收益曲线。
- 策略维度收益归因。
- 多账户汇总。

建议数据表：

```text
account
account_asset
account_position
portfolio
portfolio_snapshot
```

### 5.8 任务调度

保留现有 `ScheduledTasks`、`task`、`execute_info`，补充：

- 任务锁和幂等键。
- 失败重试次数。
- 超时和取消状态。
- 手工重跑。
- 任务依赖关系。
- 任务执行日志。

### 5.9 报表与审计

报表：

- 资产日报。
- 持仓日报。
- 订单和成交报表。
- 策略收益报表。
- 风控拒单报表。
- 数据同步报表。

审计：

- 登录日志。
- 用户操作日志。
- 策略启停日志。
- 风控决策日志。
- 订单请求和响应日志。
- 配置修改历史。

### 7.12 本阶段实现边界与验收标准

本阶段已完成参考图风格的深色终端静态界面，并接入现有只读接口：行情总览读取 `/api/market/health`、`/api/market/stocks`；账户和持仓页面读取 `/api/trade/queryAccount`、`/api/trade/holdings`。接口不可用或未登录时必须显示空状态，不得使用示例数据冒充真实账户数据。

当前 `trade.mode=readonly` 是默认安全配置。界面可以查询账户、持仓、委托和成交，但买入、卖出、撤单按钮不得触发真实交易；只有在服务端显式切换为 `real` 并通过风控、权限和二次确认后，才允许开放交易执行。

验收要求：

- 左侧 9 个导航页面可切换，当前页面有金色高亮。
- 顶部显示行情服务状态和当前账户资产读取状态。
- 行情服务正常时，行情表格由后端数据刷新；服务异常时保留可识别的空状态。
- 指数预览通过 `/api/market/indices` 从后端读取六个指数，后端适配新浪 `hq.sinajs.cn` HTTP 行情接口，前端每 5 秒刷新；当前采用 HTTP 轮询，不采用 WebSocket，页面不得直接请求第三方行情站点。
- 账户页面显示总资产和可用资金；持仓接口返回数据时显示代码、名称、持仓、可用、成本价、最新价、盈亏和收益率。
- 页面中的回测、策略、因子、风控、数据中心为功能框架，后续接入接口前必须标注“待接入”，不得宣称已经执行真实任务。
- 所有异步任务显示进度、耗时和错误信息。
- 移动端只提供查看和告警，不提供默认实盘下单能力。

## 8. 数据与安全要求

- 密码使用 BCrypt/Argon2 等单向哈希。
- 交易账户密码、Cookie、验证码密钥加密存储。
- 生产环境禁止使用默认数据库密码。
- API、前端和数据库均使用最小权限。
- 订单和风控日志不可修改，只允许追加。
- 所有时间统一存储为服务器时区或 UTC，并在前端转换展示。
- 数据库每日备份，至少保留 7 个恢复点。
- 生产环境必须提供 Mock 交易开关和全局 kill switch。

## 9. 非功能需求

### 性能

- 普通查询接口 P95 小于 500ms。
- 行情列表支持至少 5,000 个标的分页查询。
- 订单状态同步不得阻塞 Web 请求线程。

### 可用性

- 任务失败可重试。
- 外部接口超时必须快速失败。
- 交易接口异常不能导致策略线程整体退出。

### 可观测性

- 结构化日志。
- 请求 ID 和订单 ID 贯穿全链路。
- 任务、订单、风控事件可按 ID 查询。
- 后期接入 Prometheus/Grafana。

8. 任务列表、手工执行和日志。

暂不纳入第一期：

- 多券商并行接入。
- 高频交易。
- 分布式回测集群。
- 自动参数优化集群。
- 移动端实盘下单。

## 11. 验收标准

- 用户可以登录并访问受保护接口。
- 未登录请求返回 401。
- 行情数据可以查询并标记更新时间。
- Mock 模式下可以完成创建订单、成交、撤单和持仓更新。
- 超过风控规则的订单被拒绝并留下风控事件。
- 任务失败显示错误和重试状态。
- 仪表盘数据与账户、持仓、订单数据一致。
- 所有真实交易操作可以追溯到用户、策略、规则和订单。
